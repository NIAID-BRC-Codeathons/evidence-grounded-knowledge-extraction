LitRAG system overview

Evidence-grounded literature curation
One pipeline, two user interfaces

LitRAG turns an organism, optional genes, and a data type into a structured, citation-resolved result. The CLI, browser UI, and batch runner all call the same Python pipeline, so validation, extraction, deduplication, and provenance behave consistently.

The hosted path lets RAGStack retrieve and generate. The local path retrieves first, builds a LitRAG prompt, then calls an OpenAI-compatible model endpoint.

1. Interfaces and request setup

  • CLI: litrag query, batch, metadata commands, and serve.
  • Web: FastAPI serves the browser and /api/query, preview, metadata, and export routes.
  • Batch: TSV, CSV, JSON, or YAML specs run with bounded concurrency and resumable JSONL progress.
  • Inputs become a QuerySpec: organism, genes, terms, data type, collections, top-k, backend, and output policy.

2. Templates and retrieval

  • Templates define required slots, output columns, labels, versions, hashes, and token limits.
  • Server templates come from /v1/prompt-templates; LitRAG adds local types such as AST and glycosylation.
  • Default local retrieval uses fused hybrid + BM25 rankings; other modes include hybrid, vector, and BM25.
  • RAGStack returns ranked passages, identifiers, scores, and character spans. The chunk is the evidence unit.

3. Generation and extraction

  • Hosted: one /v1/query request performs server-side retrieval and generation.
  • Local: LitRAG sizes the context and output, builds a prompt, and calls Qwen, Llama, or another compatible endpoint.
  • The extractor tolerates fenced and pipe tables, malformed alignment, transposed tables, and compound rows.
  • Citation markers and author references are resolved back to retrieved sources; unsupported or incomplete rows are flagged or dropped.

4. Normalize, merge, and explain

  • Normalization standardizes genes, mutations, sites, antibiotics, interaction labels, and SIR values for comparison.
  • Template-specific identity rules merge equivalent facts while retaining variants, citations, chunk IDs, and support counts.
  • Every row receives provenance: query ID, template version/hash, model, collection, top-k, retrieval mode, timestamp, request ID, generator, endpoint, and prompt hash.
  • Results render as terminal tables, TSV, CSV, JSON, JSONL, Markdown, or interactive source-linked tables.
Evidence boundary. LitRAG is read-only against RAGStack: it retrieves and cites literature but does not ingest data, administer collections, grade answers, or manage the backend. Model output is nondeterministic; provenance and chunk-level citations make each result inspectable rather than claiming certainty.

Runtime facts

Package
Python 3.9+, packaged with setuptools; uv sync creates the environment.
Entry point
litrag = litrag.cli:main; web server uses Uvicorn and FastAPI.
Configuration
API key is read by the server process from the explicit option, LITRAG_API_KEY, or the user config file. It is not sent to the browser.
Test boundary
Tests use fixtures and HTTP mock transports; live RAGStack and model behavior are outside the test suite.
